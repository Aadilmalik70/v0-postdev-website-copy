Search intent analysis asks what job the current result page appears to solve. It should happen before you copy headings, choose a word count, or create a new URL. Use the [SERP competitor analysis guide](/blog/serp-competitor-analysis-guide) after this step to compare the ranking pages and choose an action.

The familiar labels—informational, commercial, transactional, navigational, and local—are useful editorial shorthand. They are not a claim about Google's internal taxonomy. The evidence is the result page itself: the page types, promises, features, and paths users are being offered for a specific query and context.

## Start with the decision, not the keyword

Before opening a tool, write the decision you are trying to make:

- Should an existing page be refreshed?
- Does a distinct intent justify a new page?
- Is the query a realistic fit for a product, comparison, guide, or tool?
- Is the apparent ranking problem actually a weak search snippet?
- Should the team avoid this query for now?

Without a decision, intent analysis becomes a description of the SERP rather than a useful input.

## The evidence hierarchy

Use stronger evidence before weaker clues:

| Evidence | What to record | Why it matters |
|---|---|---|
| Ranking page types | Product, category, comparison, guide, tool, forum, video, local result | Shows the formats repeatedly satisfying the query |
| Result promises | Choose, compare, learn, calculate, download, buy, visit | Reveals the job each result claims to complete |
| SERP features | AI result, snippet, video, image, shopping, local, discussion, other visible element | Changes how much of the job is completed on the result page |
| Repeated subtopics | Questions, criteria, entities, examples, constraints | Identifies necessary coverage without copying one page |
| Query modifiers | best, price, near me, template, how, alternative | Useful clue, but weaker than the live result set |

Do not decide intent from the modifier alone. A query containing “best” may return editorial lists, vendor pages, community discussion, or a mixed result page.

## Step 1: capture a reproducible SERP

Record the query, date, country, language, device, city when relevant, and data source. Search results can vary by those conditions. Use a clean browser session or a SERP provider whose settings you can document.

The [free SERP analysis template](/blog/serp-analysis-template) gives you the fields and a downloadable CSV.

## Step 2: classify each result by page type

Create a simple count:

```text
Comparison articles: __
Vendor product or pricing pages: __
Educational guides: __
Free tools or calculators: __
Community discussions: __
Videos: __
Local or shopping results: __
Other: __
```

The dominant type is a starting point, not an instruction to imitate. Look for a repeated job. If most results help users compare products, a definition-only article is unlikely to satisfy the same decision.

## Step 3: summarize each result's promise

Rewrite each visible title or snippet as a verb phrase:

- compare current plans
- choose a platform
- download a template
- inspect a live result page
- learn a process
- solve a specific technical problem

This removes marketing language and exposes the action the result promises.

## Step 4: identify mixed intent

A mixed SERP contains two or more meaningful result patterns. Treat that as uncertainty, not permission to combine every topic into one page.

Choose among four responses:

1. **Own the dominant job.** Make one page unambiguously useful for the most repeated intent.
2. **Choose the business-relevant minority.** Accept that the ceiling may be lower because the SERP is mixed.
3. **Build separate owners.** Do this only when each intent is independently useful and the pages will not duplicate one another.
4. **Defer.** Avoid a query when the result set is too unstable or misaligned with the product.

## Step 5: compare the current page promise

Write the promise of your page in one sentence. Then compare it with the result set:

| Finding | Likely diagnosis | Possible action |
|---|---|---|
| Same job, weak proof | Content or authority gap | Add original evidence, examples, or expert review |
| Different job | Intent gap | Reframe the page or assign a different URL owner |
| Right job, wrong format | Format gap | Add the useful tool, table, template, or decision path |
| Right page already appears, low CTR | Snippet gap | Test title and description after confirming the query mix |
| Stronger domains dominate despite good fit | Authority gap | Improve distribution and proof or defer |

Do not default to a complete rewrite. Preserve parts that already satisfy the intent and change only the diagnosed gap.

## Intent analysis for existing pages

Use this order:

1. Check whether the page is indexed and receiving impressions.
2. Segment the queries that surface the page where data permits.
3. Inspect representative live SERPs.
4. Compare the page's visible promise and format.
5. Separate a ranking gap from a CTR gap.
6. Choose one controlled improvement.
7. Measure after a declared window.

If a page already receives qualified impressions, an intent-aligned refresh may be more useful than publishing another article.

## Intent analysis for new pages

A new page should pass all six checks:

- the query represents a distinct job
- the audience matters to the business
- the site can add original or unusually useful value
- the page has a clear parent pillar
- existing pages can link to it naturally
- the page ends in a relevant next step

Google's guidance emphasizes content created to benefit people and asks whether the site has an intended audience and first-hand expertise. It also warns against producing many pages mainly to attract search traffic. Review [Google's people-first content guidance](https://developers.google.com/search/docs/fundamentals/creating-helpful-content) before turning query variants into separate URLs.

## Common mistakes

### Treating word count as intent

Length does not define the job. A useful template may be short; a verified comparison may require detail. Google states there is no ideal page length for generative AI search and warns against creating separate pages for every possible query variation. [Google's generative AI optimization guidance](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide) reinforces that principle.

### Copying the top result

The top result is one competitor, not the specification. Compare repeated patterns across several results and add information gain.

### Mixing a tool list with a tutorial

A software-selection page and a step-by-step analysis guide can mention the same concepts while owning different jobs. Make the primary promise explicit.

### Ignoring zero-click paths

A visible answer, AI feature, video, local pack, or tool may satisfy part of the task before a classic organic click. Record the result-page experience before estimating opportunity.

## Frequently asked questions

### What are the main types of search intent?

Informational, commercial, transactional, navigational, and local are common working labels. Use them for editorial planning, but validate the actual result-page pattern for the query.

### How many results should I inspect?

Inspect enough results to see repeated page types and promises. Ten organic results are a practical manual starting point, but mixed or feature-heavy SERPs may require a broader review.

### Can an AI tool identify search intent?

It can classify saved result data and summarize patterns. A human should verify the live context, ambiguous pages, and the business decision before publishing or rewriting.

### What if the SERP intent changes over time?

Save the original capture and repeat it after a meaningful interval. Use [competitive benchmarking](/blog/how-to-do-seo-competitive-benchmarking-2026) when the time dimension matters.

### Should mixed intent be split into multiple pages?

Only when each page solves a distinct useful job and has its own evidence, internal links, and conversion path. Do not split pages solely to target more variants.

## Final rule

Search intent analysis is complete when it changes a decision. The output should be: **keep, refresh, split, create, or defer**—with evidence and an owner.
