# Topical map: AI SEO Tools and SERP Intelligence

Date: 2026-08-03  
Market: English-language, primarily US-facing  
Audience: SaaS founders, lean growth teams, SEO practitioners, and agencies choosing tools or turning search evidence into page-level actions

## Editorial rule

Every URL owns one audience job. A new page is justified only when it has:

1. distinct intent
2. business relevance
3. original or unusually useful value
4. a parent pillar
5. natural internal-link sources
6. a measurable next step

No search volume is claimed in this map. Topic decisions use the existing page inventory, recent GSC page evidence, live-result research, and product capability boundaries.

## Internal-link contract

### Pillar to support

- Each pillar contains an in-body topic map linking to every supporting guide.
- The anchor describes the reader's next decision rather than repeating one exact phrase everywhere.
- The blog index presents the pillar first and all supporting guides underneath it.

### Support to pillar

- Every supporting guide links to its pillar in the opening section, normally within the first 100 words.
- The supporting guide states the boundary between its narrow job and the pillar's broader job.

### Sibling and cross-cluster links

- Each support page links to one or two sibling pages only where a real workflow handoff exists.
- AI SEO Tools → SERP Intelligence when software selection becomes query inspection or competitor interpretation.
- SERP Intelligence → AI SEO Tools only when the reader needs to choose the evidence source or software stack.
- No page links to every article merely to increase link count.

### Conversion path

- Commercial tool pages can hand off to pricing or the free Growth Audit.
- Informational SERP pages hand off to a worksheet, a worked example, the free Growth Audit, or a governed action workflow.
- Product copy must distinguish current audit, action, policy, and simulation capabilities from disabled external execution adapters.

## Product-truth boundary

Current verified state from the supplied implementation notes:

- first-party crawler: authoritative and implemented
- free homepage audit: implemented
- normalized `OperatorAction` lifecycle: implemented
- approval policy and append-only action history: implemented
- durable execution orchestration: implemented
- simulation adapter: enabled
- GitHub execution adapter: disabled
- WordPress execution adapter: disabled

Content may explain the intended operator loop, but it must not present live external changes as generally available. “Low risk” does not mean uncontrolled publishing.

## Evidence standard

- Separate first-hand observations, official documentation, vendor claims, and editorial judgment.
- Do not claim hands-on testing of paid tools unless the test was actually completed and documented.
- Verify volatile pricing on official sources and preserve a checked date.
- State when a browser or verification wall makes a result inconclusive.
- Keep Search Console page totals and query totals separate unless an export or API response contains both dimensions.
- Do not invent clients, outcomes, rankings, citations, time-to-result, or causal claims.

## Measurement after deployment

Review the two clusters as page groups, not by total site impressions alone.

### Primary measures

- qualified clicks by page
- qualified impressions and page-one impressions
- CTR for pages already near useful positions
- indexing and canonical status for new URLs
- free-audit starts and completions from cluster pages

### Guardrails

- irrelevant third-party navigational queries
- machine-shaped or operator-generated queries
- overlapping query ownership between pages
- new `www` impressions
- broken internal links or missing sitemap entries

### Timing

- Validate links, metadata, sitemap entries, rendering, and downloads immediately after deployment.
- Allow at least 14 days before another material rewrite of an existing owner page.
- Evaluate new-page discovery and indexing before making traffic claims.
- Compare a complete post-change window only after Search Console reporting lag.

## Stop condition

These clusters are structurally complete after the pillar links, supporting pages, taxonomy split, CSV asset, and factual corrections ship. Do not add another page to either cluster until new query evidence shows a distinct audience job that the current map cannot answer.
